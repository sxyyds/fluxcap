# FluxCap 绝对性能基准 — 2026-09-09（RTX 5060 Laptop）

本页是 FluxCap 自带 benchmark 在一台真实笔记本上的**绝对数字**，不包含与其他
库的同机对比（跨库对比方法论与计划见
[comparison.md](comparison.md)）。所有数字仅对下列软硬件组合有效，不可外推到
其他 GPU/驱动/OS/几何组合——这与 FluxCap 的[证据分级哲学](copy-evidence-qualification.md)
一致。

## 测试机

| 项 | 值 |
|---|---|
| OS | Windows 11 家庭版（build 26200） |
| CPU | AMD Ryzen 9 8945HX，32 逻辑核 |
| GPU | NVIDIA GeForce RTX 5060 Laptop GPU，驱动 32.0.16.1062 |
| 显示器 | 单屏 2560x1600（虚拟桌面 0,0-2560,1600，identity 旋转） |
| 构建 | MSVC / Release，commit 时 `build-agent/Release` 全量重建 |

CPU 占用说明：表中的 `CPU` 为进程总核时秒 ÷ 墙钟秒，即"平均占用几个核"
（1.0 = 一个核跑满；本机 32 核）。采样粒度 250ms，含 warmup 阶段。

## 1. CPU 路径：GDI/DIB 捕获真实虚拟桌面

```powershell
.\build\Release\fluxcap_bench.exe --frames 300 --warmup 50
```

捕获区域为完整虚拟桌面 2560x1600（含光标合成与 dirty 检测）：

```
Method                       min ms     p50 ms     p95 ms     p99 ms    mean ms          FPS
FluxCap steady-state         19.252     21.048     24.391     26.168     21.405       46.718
GDI rebuild/frame            18.642     20.902     22.842     24.365     21.011       47.594
```

**结论：全桌面 2560x1600 稳态 46.7 FPS（P50 21.0 ms/帧），平均约 0.41 核。**
持久化 DIB 帧池相对逐帧重建 GDI 对象没有劣势，两者都在 GDI `BitBlt` 的
物理成本附近。

## 2. GPU 端到端：WGC 捕获 → NV12 转换 → H.264 硬编

```powershell
.\build\Release\fluxcap_gpu_bench.exe --frames 600 --warmup 100 --media-fps 240 `
  [--window-width 1920 --window-height 1080]  # 窗口几何可调
```

benchmark 创建一个随显示器 VSync 持续变化的 D3D 测试窗口，经 WGC 捕获 →
BGRA → NV12（确定性 plane-RTV）→ 硬件 H.264。注意 WGC surface 尺寸包含
窗口边框/阴影区域，实际捕获面大于客户区；请求 3840x2160 的窗口超出
2560x1600 桌面时被 DWM 裁剪到屏幕尺寸，该行如实标注：

| 请求客户区 | 实际 WGC surface | submit→packet P50 | P95 | acquire+process+encode P50 | 消耗唯一 presentation | CPU（核） |
|---|---|---:|---:|---:|---:|---:|
| 1280x720 | 1284x767 | 0.84 ms | 0.94 ms | 4.16 ms | 240.0 /s | 1.19 |
| 1920x1080 | 1924x1127 | 1.61 ms | 1.75 ms | 4.17 ms | 239.6 /s | 1.15 |
| 3840x2160（被 DWM 裁剪） | 2568x1617 | 3.05 ms | 3.28 ms | 4.20 ms | 238.0 /s | 1.48 |

`acquire+process+encode` 的 P50 由 240 fps 媒体时基节奏主导（等待下一帧
的时间计入 acquire wait），单帧处理净成本看 `submit→packet` 一列。
三次运行全部 600/600 编码 packet 延迟覆盖、0 sequence gap、0 source drop。

**结论：240 fps 媒体时基下零丢帧；捕获→提交→硬编 packet 在 1080p 级
surface 上 P50 1.6 ms。**

## 3. GPU 合成饱和：转换与硬编吞吐上限

```powershell
.\build\Release\fluxcap_gpu_throughput_bench.exe --width=1920 --height=1080 `
  --operations=5000 --encode-operations=1000 --media-fps=240 --paced-fps=240
```

合成源（复用同一张不可变纹理，不进 WGC），测量各阶段饱和吞吐：

| 指标 | 1920x1080 | 3840x2160 |
|---|---:|---:|
| transform GPU batch 完成 | 23 448 ops/s | 5 896 ops/s |
| 顺序硬编（单线程逐帧） | 624.8 packets/s | 193.9 packets/s |
| 240 fps 定速异步管线 | 239.9/240.2 处理/接受，overwritten=0 | 189.9/240.2 处理/接受，overwritten=207 |
| CPU（核） | 1.14 | 1.27 |

**结论：本机 RTX 5060 上，BGRA→NV12 确定性转换在 1080p 约 2.3 万 ops/s、
4K 约 5.9 千 ops/s；单线程顺序硬编 1080p 625 packets/s、4K 194 packets/s。
240 fps 定速管线 1080p 零覆盖；4K 下 latest-wins 管线按设计丢弃过期帧
（overwritten=207）而不是积压。**

## 4. SharedFrameBus 真实捕获 + 跨槽广播 + 硬编

```powershell
.\build\Release\fluxcap_gpu_wgc_bus_bench.exe --size 640 --duration-ms 5000 `
  --bus-format nv12 --codec h264|hevc|av1
# Desktop Duplication 后端追加：
#   --capture-backend desktop-duplication --adapter-index 0 --output-index 0
```

640x640 ROI，10 秒测量窗（两轮 direct fast path 聚合），NV12 bus + 外部
encoder 提交：

| 后端/codec | capture→consumer P50 | submit→packet P50 | 唯一 presentation/s | 编码 packet 覆盖 | CPU（核） |
|---|---:|---:|---:|---|---:|
| WGC / H.264 | 8.25 ms | 0.72 ms | 59.9 | 600/600，copied=0 | 1.11 |
| WGC / HEVC | 7.84 ms | 0.62 ms | 59.7 | 598/598，copied=0 | ~1.1 |
| WGC / AV1 | 7.77 ms | 0.65 ms | 59.8 | 599/599，copied=0 | ~1.1 |
| DD / H.264 | 4.47 ms | 12.3 ms | 72.0 | 722/722，copied=0 | ~1.2 |

DD 行的 `submit→packet` 较高是真实桌面 60 Hz 出帧节奏下的排队效应
（DD 后端按系统 dirty 事件出帧，266 capture/s 中仅 72 为唯一 presentation），
不是转换/编码成本（同表中 WGC 行与第 3 节直接测得的编码延迟一致）。
所有行 `producer ingress copy = 0`、`encoder copied = 0`、consumer 侧零
`CopyResource`。

## 声明

- 这些是**本机绝对数字**，不是跨库对比，也不是任何最低保证。不同
  adapter/驱动/OS/几何组合必须重新测量。
- 第 2 节 4K 请求受单屏 2560x1600 限制，真实 3840x2160 WGC surface 需要
  4K 显示器；合成 4K 数字见第 3 节。
- CPU% 采样含 benchmark 自身的呈现线程与统计逻辑，不只 FluxCap 库开销。
- 复现：构建后逐条运行上述命令；命令与输出格式随 benchmark 版本演进。
